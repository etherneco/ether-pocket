GM1920 Android / Mobian dual boot — 2026-10-15
============================================

Later boot-menu update
----------------------

Both boot slots now contain the Etherneco menu. Volume Up/Down selects
etherPocket or Android 10; Power confirms. The menu switches slots on the
phone, with a one-shot marker preventing a second menu during the handoff.
The following image hashes and PC-only selection description document the
earlier installation. Current image identities are in
build/dualboot-installed.json and /etc/etherpocket/boot-images.json on
Mobian. See docs/bootmenu-2026-10-15.rst for the menu implementation,
verified paths and recovery procedure. Firmware image contents and
partition geometry were not changed by the menu installation.

then explicitly authorized an Android data reset after the 32 GiB

was re-enabled.

Primary/backup GPT CRCs for all six UFS LUNs were verified before the

Installed systems
-----------------

Mobian is native Debian ARM64 with Mobian packages, systemd, Xorg and
XFCE. Root is physically mounted from /dev/sda21, writable, with an
identity marker checked by the disk initramfs. Android is not used as a
container host. Wayland is not the active display server.

The tested kernel is 4.14.117-perf #5. Kernel patch 0006 prevents the DSI
backlight code from casting a DP connector to a DSI display. The prior
Oops terminated a commit worker and could block device_shutdown. The
patch is present in the booted kernel; glasses hotplug/output still needs
an actual retest with a suitable USB-C adapter.

Display and input
-----------------

XDG session type x11, physical 1440x3120 panel, touch and visible desktop
updates were verified. The three Xorg modesetting patches are required.
Patch 0003 was extended after a cold-boot failure: it skips inactive
CRTCs and retains shadow-damage tracking even when DIRTYFB is unsupported.
Otherwise the first inactive CRTC could permanently disable refresh and
make working touch appear broken.

The final modesetting module SHA256 is
e127c81a1b2371acd107115e79e459680ff0eed03a807fd41f67d64f139f71a9.
The libinput quirk removes invalid width axes from the vendor touchpanel.
Panel initialization sets bl_power=0 and brightness=300. Onboard starts
in the XFCE session and was visible in the captured scanout.

Mesa reports llvmpipe and Accelerated: no. Hardware GPU acceleration is
not claimed. Nreal has not displayed a verified desktop in this setup.

Selecting a system
------------------

Use Android.cmd or Mobian.cmd with the USB cable connected to this PC.
They call scripts/Switch-EtherPocket.ps1 and switch-etherpocket.py.
This is persistent dual boot selected with PC assistance, not an on-phone
boot menu. A normal power-on starts the last selected system.

Important device-specific behavior: the inactive OEM boot partition uses
the generic type GUID 77036cd4-03d5-42bb-8ed1-37e5a88baa34, while the
selected boot image uses 20117f86-e985-4357-b9ee-374bc1d8487d. On this
phone, Fastboot set_active changes slot flags without correcting those
boot type GUIDs. Flags alone were insufficient for reliable switching.

The final selector prepares canonical boot type GUIDs and boot flags
from native Mobian, verifies both GPT copies, reboots to Fastboot, then
completes global slot activation and reboots. From Android it first uses
a temporary native disk-root bridge; switching performs no image flash
or filesystem formatting. The native helper validates serial, GPT CRCs,
partition identities and the installed boot image hashes. Firmware image
contents are never copied or changed by the switcher.

A failed intermediate experiment was rolled back by restoring original
slot-B GPT types/flags while preserving partition geometry and image
contents. Android B subsequently completed boot. Do not restore whole
old GPT backup windows: they describe the old userdata extent.

Debian qbootctl 0.2.2-1 marks native slot A successful, avoiding retry
exhaustion. Its service and both slots' bootable status were checked.
Android OTA updates can replace the inactive slot; OTA-safe coexistence
has not been implemented.
