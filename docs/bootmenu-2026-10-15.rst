Stock-kernel Android handoff
----------------------------

The stock Android kernel also displayed the menu and provided rescue SSH.
``build-stock-menu-test.sh`` retains its module ABI and changes the unique
``skip_initramfs`` parameter name to allow this menu's initramfs to run.
It creates a read-only dm-verity mapping using the saved verified system_b
table and attempts to switch_root into Android's original /init.

The initial Android-init log identified fatal EBUSY failures mounting
/proc and /sys. Android FirstStageMain expects to create these mounts;
moving the menu's existing mounts into its root caused the failures.
The normal handoff now detaches the menu mounts instead. A diagnostic
boot then reached Android's visible UI, but retaining the rescue RNDIS
gadget prevented normal ADB. The normal build now leaves USB completely
to Android, unless a root-owned bootmenu-debug file explicitly enables
rescue RNDIS. This build completed an Android 10 boot with ADB and slot B
verified; see evidence/bootmenu-android-normal-boot.txt.

CURRENT DEVICE STATE: boot_b contains the stock-kernel menu with the
validated Android handoff and normal USB. The original Android boot_b is
backed up at recovery/stock-backup/boot_b.img. boot_a contains the native
menu with kernel #6. Both image prefixes were read back and verified.

The first qbootctl-based standalone slot switch also failed. The previous
GPT type identities and flags were restored from the fresh pre-test
backup using only GPT entry/header sectors, and all six GPT CRC pairs
were verified. Boot LUN A was restored using the vendor UFS ioctl. The

Reading the UFS attribute on its verified B path confirmed boot LUN 2.

The revised selector preserves non-boot firmware type GUID identities,

Rebuilding and recovery
-----------------------

With the prepared EtherPocketBuild WSL kernel, miniroot and qbootctl source
trees, regenerate assets using host Python and then run::

    python scripts/build-bootmenu-assets.py
    wsl -d EtherPocketBuild -- bash /mnt/c/projects.local/mobiam/scripts/build-bootloaders.sh

scripts/verify-bootmenu-installation.py verifies installed image prefixes,
persistent data, native services and the optional PC selector from Mobian.
Android.cmd / Mobian.cmd remain available for PC-assisted recovery, using
the original verified native disk-root bridge and the current installed
image identities. Both menu images can be replaced from Fastboot using
the saved originals; restoring only boot_b preserves the on-disk Android
data volume. Revalidate slot types and activation after any restoration.

Android OTA-safe coexistence remains outside this installation: an OTA
can replace a boot slot and its menu. The saved verity table also belongs
to this exact installed Android system image.
